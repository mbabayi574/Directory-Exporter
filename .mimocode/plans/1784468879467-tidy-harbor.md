# Plan: Grafana Dashboard for Directory Exporter

## Overview

Add a full self-contained monitoring stack (Prometheus + Grafana) with auto-provisioned dashboard and datasource, designed to work alongside the existing exporter service.

## Available Metrics

The exporter exposes 11 Prometheus metrics (5 control-plane, 6 data-plane with `base/stream/type` labels):

| Metric | Type | Description |
|--------|------|-------------|
| `directory_cache_ready` | gauge | 1 = ready, 0 = cold start |
| `directory_last_scan_timestamp_seconds` | gauge | Unix epoch of last scan |
| `directory_watched_total` | gauge | Total watched directories |
| `directory_scan_errors_total` | counter | Cumulative scan errors |
| `directory_reload_total` | counter | Cumulative reload triggers |
| `directory_file_count` | gauge (per-dir) | File count per directory |
| `directory_oldest_file_timestamp_seconds` | gauge (per-dir) | Oldest file age |
| `directory_newest_file_timestamp_seconds` | gauge (per-dir) | Newest file age |
| `directory_scrape_duration_seconds` | gauge (per-dir) | Scan duration |
| `directory_scrape_success` | gauge (per-dir) | 1 = readable, 0 = error |
| `directory_scan_truncated` | gauge (per-dir) | 1 if scan was truncated |

## Files to Create/Modify

### 1. `docker-compose.monitoring.yml` (replace existing)
Add Prometheus + Grafana services with a shared `monitoring` network:

```yaml
networks:
  monitoring:

services:
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    volumes:
      - ./monitoring/prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - prometheus_data:/prometheus
    ports:
      - "127.0.0.1:9090:9090"
    networks:
      - monitoring
    restart: unless-stopped

  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    volumes:
      - ./monitoring/grafana/provisioning:/etc/grafana/provisioning:ro
      - ./monitoring/grafana/dashboards:/var/lib/grafana/dashboards:ro
      - grafana_data:/var/lib/grafana
    ports:
      - "127.0.0.1:3000:3000"
    environment:
      GF_SECURITY_ADMIN_USER: admin
      GF_SECURITY_ADMIN_PASSWORD: admin
      GF_USERS_ALLOW_SIGN_UP: "false"
    networks:
      - monitoring
    restart: unless-stopped
    depends_on:
      - prometheus

  exporter:
    # (existing service stays in docker-compose.yml, just joins the network)
    networks:
      - monitoring

volumes:
  prometheus_data:
  grafana_data:
```

### 2. `monitoring/prometheus.yml`
Use the existing config but ensure it targets the exporter correctly on the shared network.

### 3. `monitoring/grafana/provisioning/datasources/datasource.yml`
Auto-provision Prometheus as the default datasource pointing to `http://prometheus:9090`.

### 4. `monitoring/grafana/provisioning/dashboards/dashboards.yml`
Dashboard provider that loads JSON files from `/var/lib/grafana/dashboards`.

### 5. `monitoring/grafana/dashboards/directory-exporter.json`
The main Grafana dashboard with these panels:

**Row 1 — Exporter Health**
- Stat: Cache Ready (`directory_cache_ready`) — green/red
- Stat: Last Scan Time (`directory_last_scan_timestamp_seconds` → human-readable relative time)
- Stat: Watched Directories (`directory_watched_total`)
- Stat: Uptime (Grafana built-in `up{job="directory-exporter"}`)

**Row 2 — Per-Directory Status**
- Table: Directory Status — columns: base, stream, type, file_count, scrape_success, scan_truncated
- Heatmap or bar chart: File Count per directory

**Row 3 — Data Freshness**
- Time series: Newest File Age (`now() - directory_newest_file_timestamp_seconds`) per directory
- Time series: Oldest File Age (`now() - directory_oldest_file_timestamp_seconds`) per directory

**Row 4 — Scan Performance**
- Time series: Scan Duration (`directory_scrape_duration_seconds`) per directory
- Time series: Scan Errors (`rate(directory_scan_errors_total[5m])`)
- Time series: Reload Count (`rate(directory_reload_total[5m])`)

**Row 5 — Alerts (visual only, no alerting rules)**
- Annotations for truncation events, accessibility failures, error spikes

## Dashboard Design Decisions

1. **Variable**: A `stream` template variable populated from `label_values(directory_file_count, stream)` for quick filtering
2. **Refresh**: Auto-refresh every 30s to match Prometheus scrape interval
3. **Time range**: Default last 1h, suitable for operational monitoring
4. **Colors**: Standard Grafana palette — green for healthy, yellow for degraded, red for error states

## Verification

1. Start the stack: `docker compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d --build`
2. Verify Prometheus targets: `curl http://localhost:9090/targets` — directory-exporter should be UP
3. Verify Grafana: Open `http://localhost:3000` → Login admin/admin → Dashboards → Directory Exporter
4. Verify panels populate: After first scan interval (120s), data should appear in all panels
5. Verify variable filtering: Select a stream value from the dropdown, panels should filter accordingly
